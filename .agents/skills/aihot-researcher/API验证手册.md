# aihot 来源核查

此页只用于接入与故障排查；不说明服务目前是否可用。当前入口和参数定义在
[fetch.py](fetch.py) 与 [config.json](config.json) 的 `fetch` 块。

## 发起一次有界请求

在项目根目录执行：

```bash
python .agents/skills/aihot-researcher/fetch.py --window-hours 48 --take 10
```

记录实际时间、退出码和 JSON `status`。不要通过修改 DNS、固定历史 IP、忽略 TLS
错误或重复扩大时窗把失败掩盖成成功。确实需要另一个时间窗口时显式调用并记录选择。

## 判读

| 状态 | 含义 | 后续 |
|---|---|---|
| `ok`，退出 0 | 一页合法线索 | 选择相关项，读取原始来源 |
| `empty`，退出 0 | 成功获取空列表 | 接受没有线索；按研究需求决定是否用其他来源 |
| `unavailable`，非零 | 网络、超时、HTTP 等失败 | 报告不可用；可换官方来源或网页检索 |
| `invalid_response`，非零 | 非 JSON、字段异常或响应过大 | 记录服务契约变化，修复解析前不消费内容 |
| `invalid_config`，非零 | 参数或配置不可用 | 检查配置，不增加候选要求 |

适配器只验证可消费的数据结构，不证明摘要事实正确、时间覆盖完整或文章已亲测。
`published_at` 是来源提供的发布时间；`fetched_at` 是抓取时刻，两者不能互换。
`has_more` 只是源端分页提示，不构成自动抓取全库的要求。

## 离线回归

项目系统测试 `tests/test_topic_legacy_tools.py` 使用伪造响应验证：一条线索、空列表、
失败、坏结构和预算上限，不访问线上 API。这类测试通过只能证明适配器行为；
一次真实请求才可说明该时刻的连通性，仍不能证明原文内容的真实性。
