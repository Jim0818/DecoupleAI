# ai-as-me v5.0 — 内容优先的账号写作基线

> 版本：2026-08-13 content-first baseline
> 目标：保存账号是谁、写给谁、长期写什么，以及默认怎样把内容讲清楚。
> 核心变化：`ai-as-me` 不再要求 AI 持续模拟“作者人格”或主动制造观点。内容、事实、技术与读者理解优先，评论和作者判断按需出现。

## 1. 这套基线解决什么问题

`ai-as-me` 的职责不是把每篇文章加工成“有态度的作品”，而是给 AI 一个稳定的写作起点：

- 先把对象本身讲准确；
- 再把重要机制、过程、代码、数据和边界讲清楚；
- 根据读者任务决定解释深度；
- 有真实材料或确有必要时再补充作者判断；
- 事情讲完就停，不为“作者性”“深度感”或“活人感”继续加工。

一篇文章可以主要由事实、解释、教程、代码、案例和技术细节构成。**没有鲜明观点，不是质量缺陷。**

## 2. 默认写作顺序

```text
事实与材料
→ 对象/技术本身
→ 机制与过程
→ 细节、代码、例子或证据
→ 使用边界与已知限制
→ 必要时的判断或评论
→ 任务完成后停止
```

不得把顺序反过来，让“先找一个独特判断”成为组织材料的前置任务。

## 3. 分层职责

| 层级 | 负责回答 | 不负责 |
|---|---|---|
| `L1_identity.md` | 账号身份、受众、栏目、长期内容边界、证据边界 | 固定正文结构、观点数量、句式风格 |
| `L2_values.md` | 内容价值排序、读者任务、技术深度、评论权限、信任边界 | 强制作者姿态、情绪和结论 |
| `L3_content_dna.md` | 默认叙述方式、不同内容类型如何讲清楚、账号声音范围 | 固定 H2、固定篇幅、必备金句或必备评论 |
| `_shared/活人感技法库.md` | 旧路径兼容指针；新运行不从这里加载自然写作规则 | 任何独立技法、Writer 配额、反 AI 检测规则、人格模拟 |

三账号 L1/L2/L3 的权威文件位于 `config/accounts/<account>/`；本目录的账号文件仅作兼容链接。选题长期范围以所选账号 L1/L2 为依据，当前任务再明确本次方向和材料。不要在本目录维护第二套账号规则。

## 4. 决策优先级

```text
事实与证据边界
> 当前文章的读者任务
> 技术/对象需要讲清楚的内容
> resolved Writing Contract / Claim Ledger
> writing-policy 通用质量政策
> L1 身份与平台边界
> L2 价值排序
> L3 声音范围
> 可选写作技法与历史样本
```

任何声音、风格、作者材料或竞品样本，都不得压过内容本身。自然正文执行方法不属于 `ai-as-me`：新运行统一使用 `skills/natural-prose/SKILL.md`，账号 L3 只提供声音范围。

## 5. 内容优先原则

### 5.1 事实可以直接写

已经确认的事实，不需要先套作者立场。技术说明、产品变化、API 行为、代码流程、运行结果，都可以平实地进入正文。

### 5.2 技术值得被详细介绍

硬核技术稿允许把主要篇幅用于：

- 背景与问题；
- 核心概念；
- 架构与数据流；
- 算法、模块和执行过程；
- 配置、代码、接口和参数；
- 示例、测试和结果；
- 失败模式、限制和兼容性；
- 与相关方案的必要比较。

不因为担心“像教程”“像说明书”而主动删掉真正有用的技术细节。

### 5.3 评论是可选增量

评论只在它能完成下面至少一件事时加入：

- 帮读者判断是否值得关注、使用或迁移；
- 解释一个事实为什么重要；
- 指出证据与宣传之间的明显差距；
- 说明工程成本、失败条件或现实取舍；
- 明确当前材料还不能支持什么结论。

除此之外，不为了作者存在感追加评论。

### 5.4 普通表达优先

默认使用正常现代中文，把事情说清楚即可。允许普通句子、普通过渡、普通小结，也允许技术名词和长段落。

不要主动追求：

- 每段一个判断；
- 每节一次反转；
- 每篇一个反直觉结论；
- 频繁的“真正的问题”“本质上”“更重要的是”；
- 自造术语、金句和宏大升维；
- 为了显得像人而加入虚构场景、口头禅、自嘲和情绪。

### 5.5 Agent 上手、教程与试用

主流 Agent 的第一次使用、具体任务教程、真实试用和选择比较，均可按相应账号的读者任务进入选题。简单使用问题可以独立成篇；Skill、MCP、源码和复杂工作流只在帮助完成任务时出现。具体账号范围仍由 L1/L2/L3 决定，不设固定品牌清单或候选配额。

工具介绍、操作指南、真实试用和对比是不同内容承诺，不是固定生产阶段。材料怎样支持措辞、关键操作是否执行、结果如何核查，统一参照 [工具教程与试用](../skills/research/references/tool-trials.md)。试用记录保留实际执行主体：作者、当前 Agent 或第三方；当前 Agent 的本次执行不能自动写成作者的长期使用经历。

## 6. “活人感”的新定义

活人感首先来自**正常的信息选择和自然语言**，不是作者必须持续出镜。

可信的人味可以来自：

- 材料有具体来源；
- 解释有轻重，不平均用力；
- 有必要的取舍，而不是事无巨细复制资料；
- 遇到不知道的地方正常承认；
- 有真实体验时写体验，没有就不装；
- 偶尔出现自然判断，但不把判断加工成姿态。

一篇几乎没有第一人称、没有金句、没有尖锐评论的技术文章，也可以很像人写的。

## 7. 材料与篇幅

- 新段落应增加事实、解释、步骤、例子、代码、区别、结果或边界中的至少一种新信息。
- 同一个意思反复换说法，不算内容增量。
- 材料不足时缩小题目、缩短篇幅或继续研究，不用评论和抽象总结填字数。
- 材料丰富时允许写长，不为追求“精炼”牺牲理解技术所需的细节。

## 8. 使用原则

1. 账号声音是一个范围，不是一套句模。
2. 文章价值默认由内容承担，作者判断不再是必填项。
3. 栏目定义读者能得到什么，不定义必须出现多少观点、故事或评论。
4. Writer 不需要寻找“作者最在意的一点”才能开始写作。
5. Refiner 的主要任务是删掉重复、虚假姿态、机械结构和不自然表达，不得为了“更像人”主动增加评论。
6. Reviewer 不以观点密度、金句数量、第一人称存在感或“独特判断”作为质量指标。
7. Style Analyst 只保留长期稳定的内容偏好、解释深度和语气范围，不把爆款姿态写回账号 DNA。

`assisted/` 为独立业务账号资料，不参与三个媒体账号的默认加载。
