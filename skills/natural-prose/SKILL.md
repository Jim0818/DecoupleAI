# Natural Prose — 朴素自然正文

用已有可靠材料，把具体问题、解释与判断自然地讲下去。保留技术深度、真实反应和有效的原稿表达。

## 1. 适用边界

在当前任务内选择材料顺序、展开深度和表达，不替主管改选题，也不补造事实或证据。Revision 2 的少量非关键情境细节服从 §5。

| mode | 使用者 | 任务 |
|---|---|---|
| `compose` | 写作员工 compose / edit | 新稿按材料组织；原稿编辑保留有效表达与任务范围 |
| `review` | 独立审阅员工 | 检查理解、可信度、阅读任务及用户明确的表达要求 |
| `refine` | 写作员工 repair | 只修允许的问题及必要上下文 |

使用任务提供的范围、材料权限和有效结构政策。主管上下文提供当前 `prose_policy_revision=2`。显式请求退役政策时报告不支持，不自动升级或改写历史稿件。本 Skill 不另造输出格式或固定流程。

## 2. 五条总原则

### 2.1 先处理事情，允许人正常说话

正文像懂行的同事讲清一件事：先交代具体对象或问题，用直接动词说明动作，再顺着事实、机制、步骤、例子、结果和有边界的判断推进。可以自然使用“但、所以、比如”等承接，它们要承担真实关系，不按段落撒口头禅。允许有用的叙事停顿和取舍，不为了“更像人”强造金句、反转或作者姿态。

### 2.2 相邻段落有可理解的推进关系

围绕读者问题决定下一段为什么出现：现象需要解释，结果需要证据，操作产生新状态，建议需要条件。具体材料应承担作用，内部覆盖清单不决定段落顺序。

真实反应、必要停顿和与读者的联系也可以有作用，不要求每句话新增事实。同一结论反复换说法，却未增加解释、条件或情绪上的进展，才需要合并。

### 2.3 结构优先藏在局部语义关系里

正常正文不需要不断告诉读者“下面讲什么”。优先让相邻句段形成接力：对象续接、结果补因、机制落地、问题直答、限制回压。

只有认知任务真正换层时，才考虑显式结构。

### 2.4 有取舍，也有证据附近的判断

核心机制充分展开，共同背景简短处理，无关材料移出本篇。判断可以说明为什么关注、如何取舍、哪里意外或尚拿不准；让读者看到它所依据的事实和条件。

去掉“我觉得”后仍应能辨认判断的作用。材料适合技术解释时，把技术讲清即可，不为作者出场制造观点。

### 2.5 完成即停止

读者任务已完成、必要边界已交代，就结束。Revision 2 的硬技术稿若用了 H2，最后一节按结构政策用 `## 写在最后` 收束已有问题、选择或边界；不重复全文，也不补“时代意义”。无 H2 的稿件自然停下。

## 3. 按材料选择推进动作

接住前文的对象、结果或问题，按当前缺口补原因、术语、具体操作、证据或限制。术语到真正影响理解时再解释；例子解决理解或操作困难，贯穿案例每次回来都推进状态或边界。

这些动作按需使用，不构成固定顺序。核心机制可以连续多段，普通处一句带过。推进卡住时再读 `references/progression.md`。

## 4. 结构路由

### 4.1 `continuous_editorial`

Revision 2 的普通文章、情报、产品更新、工具介绍、行业观察、普通分析、复盘和一般教程均采用这一类。

默认要求：

- narrative H2 = 0；
- 不用 H3/H4、`01 PART`、单行粗体总结、`写在最后` 等伪标题代偿；
- 不用“背景 / 核心变化 / 真正影响 / 最后怎么看”式目录推进；
- 背景随当前理解缺口补入；
- 段落之间靠内容关系衔接。

情报类具体写法见 `references/intelligence-writing.md`。

### 4.2 `hard_technical`

硬核技术文 **H2 allowed, not required**。出现代码或安装命令本身不构成硬技术分节理由；用了 H2 时服从正文结构政策的末节规则。

只有下列认知换层确实需要导航时才开 H2：

- 是什么 → 怎么实现；
- 机制 → 实验/验证；
- 原理 → 安装/操作；
- 一个技术层级 → 另一个技术层级。

H2 优先用对象名、组件名、任务名或实验名，不用“真正的突破”“最值得关注”这类评论标题。

技术保护规则见 `references/hard-tech-writing.md`。

## 5. 信息权限、知识来路与作者存在感

第一人称可以说明知识来路、真实行动、选择理由、失败和仍拿不准的判断。

没有亲历材料，可以完全不写“我”，也可以在证据支持时写条件推演，例如“如果我来配置，会先把重试限制在幂等请求上”。这种表述不能变成过去时部署、踩坑、收益或用户反馈。缺第一人称、缺故事、缺鲜明观点本身都不是缺陷。

资料解读在知识来路影响可信度或解释时，保留必要来源归属、材料取舍或未知项。是否能写“我查了 / 我试了 / 我改了判断”，服从实际作者材料与第一人称权限，不能把公开材料升级成亲历。

直接讲整理后的问题、结论和边界，不为背书复述内部编辑过程。来源身份影响证据责任、版权或用户明确要求时，说明必要来路；账号口吻不能抹去来源身份。

Revision 2 可依真实事实补少量非关键情境细节，但不得改变事实骨架、技术操作、结果、因果或来源身份，不得进入真实证据或作者材料。会让读者误认作者亲测、部署、报错、获益或收到用户反馈的细节应改写或删去。

表达参考只帮助理解如何取舍、解释和承接。不得搬用参考作者的经历、观点或类比；发布、审阅 PASS、现稿版本都不自动代表用户认可了其中的文风。

知识来路不是新配额。不要每隔两段重复“公开资料显示 / 目前无法确认 / 可以确认的是”，让后台核验笔记接管正文。具体写法见 `references/epistemic-texture.md`。

## 6. 开头

从最能引出当前问题的已有材料进入，后文接住开头。事件要影响本文对象，经历要带出问题或选择；没有这类材料就直接解释具体对象，不补通用亲历包装。

事件、任务、问题、结果、场景或必要定义都可作入口。讲解像熟悉同事间自然解释，不必显式称呼读者身份，也不固定用热络招呼开场。

版本、口径和限制贴近它们约束的事实，必要边界仍在首次影响可信度的位置交代。不要先预告文章结构，也不要在首段堆满后台核验说明。

## 7. `compose` 模式

1. 读取读者任务、材料与边界；编辑原稿时先辨认需保留的有效内容。关键机制或过程不能仅凭摘要还原时，按需回读原始片段、代码或记录；缺材料就缩小范围或报告缺口。
2. 使用当前 `prose_policy_revision=2` 与有效结构类；缺省普通稿 continuous_editorial，需要技术分节时由写作员工按稿件性质选择 hard_technical。显式退役政策或未知结构类应报错。
3. 按 §6 进入具体问题，再按 §2—3 安排详略和顺序；不为节奏制造短句、转折或平均篇幅。
4. 需要判断时靠近其证据，说明条件；来源、作者表达及情境细节服从 §5。
5. 保留有作用的例子、真实反应与停顿；技术任务保护代码、参数、条件链、实验口径和必要长段。
6. 当前任务完成后停止，检查相邻概括和收束是否反复承担同一作用。

输出只交调用者要求的正文或结构化产物，不报告“用了哪些人味技巧”。

## 8. `review` 模式

根据本次任务检查正确性、理解、证据边界、导航、可操作性和表达要求。用户要求改善自然度或口吻时，检查具体反馈是否解决，仍以可定位的问题动作说明理由。不要仅凭个人审美判全文需要润色。

优先识别这些问题动作：

- 多个段落重复同一判断，没有增加解释、条件、行动或有作用的反应；
- 相邻句段对象突然断开，读者不知道为什么跳到下一件事；
- 背景提前成块，抽象判断却迟迟没有材料或机制落地；
- 开场堆放版本、免责声明与覆盖目录，具体对象和问题迟迟不出现；
- 事件或经历与后文没有因果或问题上的接续；
- 评论说得比证据大，或离证据太远；
- 第一人称只套在原有结论上，新增的作者出场没有承担信息或判断作用；
- 连续制造假升级，或以覆盖清单、H2、伪标题替代推进；结构违规按 §4 的有效政策判断；
- 技术正文为了“自然”丢掉参数、条件、代码或机制；
- 非关键情境细节越界成亲历或证据，或连续装饰而拖慢理解；
- 来源归属和核验说明反复出现，把后台查证笔记写成机构腔；
- 动作长期被“进行了 / 实现了 / 完成了对……”一类名词化结构藏起来，主干因此难读；
- 正文已经完成，却继续总结、升维或写 CTA。

以下情况**不能单独构成 finding**：

- 出现正常标点、问句、转折或承接词；
- 没有第一人称、观点、反转或金句；
- 长技术段、长短不均或有作用的停顿；
- 有效结构政策允许的直接导航 H2。

确定性 prose signal 只能作为候选位置。finding 应说明位置、具体问题、读者影响和最小修复方向；没有实质问题就通过，不为证明审阅有用而制造修改。

## 9. `refine` 模式

只修允许的问题及必要上下文。先保护已经有效的表达：有据的来源与判断、真实的不确定性、技术细节、自然停顿和材料形成的长短不均。正确事实不因文风修改失去条件；真实错误则依据材料修正。

随后按优先级修：

1. 删除重复解释、空评论、自动升维和完成后的尾巴；
2. 合并只换说法的段落；
3. 调整局部顺序，让对象、结果、原因和例子重新接上；
4. 把抽象判断还原到已有事实、动作或边界；
5. 动作被名词化、主干明显来得太晚时，优先恢复直接动词；
6. 必要时补已有材料支持的解释或预期状态，再修转场；不为每节补“比如”，不增加新观点、新证据或无关故事。

具体修复动作见 `references/revision-actions.md`。

局部修订不做全篇“人味美容”，也不把技术内容缩短成移动端短句。

## 10. 不采用的伪规则

- 固定短句率、段落长度或句长方差；
- 第一人称、观点、设问、金句数量配额；
- 禁冒号、禁破折号、禁某一种正常中文句式；
- 为“活人感”主动添加粗口、错字、括号吐槽、假场景；
- 强制每篇有故事、冲突、反转或升华；
- 把任何单一博主的口头禅当默认风格；
- 用加权分数评价“人味”。

字面形式只有在**重复执行坏动作**时才值得修，例如连续用同一种翻案句制造假洞察。
