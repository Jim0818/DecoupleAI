# Natural Prose · 知识来路纹理

> 仅在来源、核对过程、真实判断变化或未知项会影响可信度、解释或选择时加载。它处理**怎么表达已获授权的知识来路**，不负责事实核验，也不新增作者经历。

## 1. 先区分“知道什么”和“要不要写我怎么知道”

TextPicOS 的 Evidence / Claim / Author Input 契约先决定事实权限。本 reference 只决定其中哪一小部分值得进入正文。

知识来路进入正文，至少要完成一项工作：

- 解释为什么采用这份材料而不是另一份；
- 说明某个结论为什么只能写到当前强度；
- 交代一条材料如何改变了比较、选择或理解；
- 区分公开资料、官方自述、第三方测试和已验证操作；
- 把一个会影响读者判断的未知项说清楚。

都不需要时，直接写事实和机制即可。

## 2. 四种可用纹理

### 2.1 中性来源归属

不需要第一人称，也能让读者知道知识边界。

```text
官方文档确认了 256K 上下文，但没有给生产环境的稳定性数据。
```

适合 source-led 情报、技术说明和事实稿。

### 2.2 来源核对痕迹

只有 first-person permission 允许 source disclosure，且核对过程确实帮助理解时才写。

```text
我把这次 API 文档和上个月的版本说明对了一遍，价格表变了，限流说明没有一起更新。
```

它的价值是解释“为什么这里还不能下稳定性结论”，不是证明作者很认真。

### 2.3 真实判断变化

必须真的存在前后材料变化，不能先造一个笨误区再反转。

```text
最初我更在意上下文长度。把三组批处理账单放在一起后，实际差距主要来自失败重试，判断也跟着变了。
```

如果没有可追溯的前后判断，直接写当前结论。

### 2.4 有用的未知项

未知项只在它会改变结论、选择或风险时出现。

```text
现在还缺一项数据：长请求在高并发下的失败分布。这个数字没出来前，不能把小规模测试直接外推到生产环境。
```

不要把每条来源的不完整都写成“目前无法确认”。

## 3. verified operation 和 source-led 不能互相冒名

- `verified_experience` 才能写“我部署 / 我跑了 / 我试了 / 我踩到”；
- `source_disclosure` 只允许写查阅、核对、比较公开材料，不等于亲测；
- `none` 时使用中性来源归属，不写第一人称分析轨迹；可以表达基于现有证据的条件选择，但不得暗示已经查证、部署或实测；
- 公司自述、媒体报道、第三方测试保持各自身份。

信息来路越具体，权限要求越高。不要用一句“我研究了一下”把公开资料升级成实践经验。

## 4. 同一来源边界一次说明通常够了

这些句子连续出现时，正文会变成核验报告：

```text
公开资料显示……
目前无法确认……
可以确认的是……
从现有资料来看……
```

如果它们都在处理同一来源、版本、测量口径和确定性边界，合并成一次最有用的说明，后面继续讲事情。换了来源，版本或口径变化，或者从已确认事实转到推断时，要在变化处重新归因。

来源归属的目标是**让读者知道结论为什么只到这里**，不是让作者反复证明自己谨慎。

## 5. 细节必须有工作

一个细节值得保留，至少改变以下一项：

- 证据强度；
- 机制理解；
- 成本或时间；
- 角色选择；
- 失败原因；
- 适用边界；
- 下一步行动。

例如：

```text
一次导出 500 份文档时，网页端要反复点开页面；CLI 可以按空间一次筛完。
```

“500 份”改变了工具价值的解释，因此有工作。

下面这类细节如果没有来源，也不改变后文，删除：

```text
凌晨两点，桌上的咖啡已经凉了，我盯着屏幕又试了一次。
```

不要靠假现场补“真人感”。

## 6. 不要替读者多解释一步

动作、数字、原话或前后变化已经把后果交出来时，可以停住。

```text
失败后它会从头重跑整个批次。200 份文档时，一次错误就多等十几分钟。
```

如果下一句只是“这让高频任务的体验非常糟糕”，通常已经没有新增信息。

留白只省掉读者能够自己得到的解释；关键因果、限制和行动条件仍要写清。

## 7. Reviewer 冷读四问

只把答案转成**可定位、可修复**的 finding，不输出“人味分”。

1. 哪一处能让我知道这段话凭什么成立？如果本来不需要显式来源，不制造问题。
2. 哪个细节改变了理解，哪个只在装饰现场？
3. 哪句话说得比材料大，或把未知写成了确定？
4. 文章在哪一句已经完成 reader task？后面的内容还有没有新工作？

## 8. 不采用的做法

- 不要求每篇都出现“我查了 / 我看了 / 我发现”；
- 不要求每篇都有判断变化；
- 不要求主动暴露检索过程；
- 不把“公开资料显示”当固定开场；
- 不用第一人称次数评价作者存在感；
- 不为了“真实”添加时间、天气、神态、房间、烟酒和对白。
