# Natural Prose · 朴素中文表达

> 用于句子明显端着、主干太晚、词汇被过度“优化”或段落节奏被刻意设计时加载。

## 1. 朴素不等于全篇聊天

目标不是把所有句子改成聊天语气，而是让读者尽早知道：

- 谁或什么在做事；
- 做了什么；
- 出现什么结果；
- 条件和限制是什么。

普通技术词、标准书面语、长句都可以保留。

适量口语能让关系更直接。比如“但这里有个问题”“所以先看配置”“说到这一步，还差一次验证”，都可以用；前提是后文确实处理这个问题、配置或验证。不要每段都补一句主持人口吻，也不要把整篇统一改成聊天语气。

## 2. 对象和动作尽早出现

### 偏重

```text
在经过多轮不同参数组合、数据规模和运行环境下的重复验证之后，我们最终能够观察到的一个比较明确的结果是，缓存策略对长请求的收益明显更高。
```

### 直接

```text
多轮测试后，缓存策略对长请求的收益明显更高。不同参数和数据规模下，这个趋势都没有变。
```

不是为了变短，而是先把结果交出来。

## 3. 普通连接词可以正常用

“但、所以、比如、不过、其实、然后、这个、它”都属于正常中文。

不需要为了“词汇丰富”轮换成：

- 然而；
- 与此同时；
- 由此可见；
- 值得注意的是；
- 更深一层；
- 从另一个维度看。

后者也不是禁词，只在真的承担对应逻辑时使用。

也可以直接和读者交换一个具体信息：

```text
先看 timeout。它限制的是单次等待，不是整个任务一定会在 3 秒内结束。
```

这种“先看”把注意力交给真正影响理解的对象。它不是语气装饰，也不需要全文反复使用。

## 4. 不机械改短句

复杂关系需要一口气讲清时，可以使用长句。

```text
如果任务本身允许少量漏项，但不能接受模型补出不存在的字段，那么结构化抽取的稳定性比平均响应速度更重要。
```

把它拆成四句不会更自然。

连续很多单句成段也可能形成刻意鼓点。段落长度服从材料。

## 5. 不为避免重复强行换名词

同一对象连续出现时，正常重复名字或使用“它 / 这个结果 / 这项更新”即可。

不要把一个产品轮流写成“这款工具 / 这一系统 / 该解决方案 / 这个能力载体”，这种同义替换反而容易产生模型腔。

## 6. 动作别藏进名词里

机构腔经常不是词太正式，而是**做事的人和动作消失了**。

```text
对缓存策略进行了优化。
实现了失败率的下降。
完成了对重试流程的调整。
```

优先还原成直接动作：

```text
我们改了缓存策略。
失败率从 8% 降到 3%。
重试流程现在只重跑失败任务。
```

不是所有“进行 / 实现 / 完成”都要删。只有它让句子失去具体动作、责任主体或可观察结果时才修。

## 7. 抽象词后面要有人、动作或后果

如果一句话出现“效率、体验、价值、能力、趋势、生态、范式”，看下一句有没有回答：

- 谁更快；
- 少了多少步骤；
- 省了多少钱；
- 哪个任务现在能做；
- 哪个失败消失了；
- 谁需要改变选择。

有具体含义就保留；只是给普通事实抬价就删。

## 8. 允许正常的不完美

自然正文可以：

- 同一个词短距离重复；
- 先说结果再补条件；
- 插一句有限的自我修正；
- 某一段比旁边长很多；
- 用括号补一个必要信息；
- 某个普通段落平平地结束。

不要为了“更像人”故意制造语病、错字、粗口或随机岔话。

## 9. 句式不是质量单位

冒号、破折号、问句、对照句、排比都可以出现。

检查的是它们在做什么：

- 是真的解释关系，还是充当万能路标；
- 是真实自我修正，还是先造误区再反转；
- 是两个必要并列项，还是为了气势重复结构；
- 是技术定义，还是把普通事实包装成“洞察”。

动作合理就保留。
