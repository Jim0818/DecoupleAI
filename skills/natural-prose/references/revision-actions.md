# Natural Prose · Reviewer / Refiner 局部修复动作

> 只在已有 draft 和明确 review finding 时加载。目标是修最小必要范围，不做全篇润色。

## 1. Finding 判断顺序

先问：这个问题是否实际伤害了理解、证据边界、导航、可操作性或任务完成？

如果只是“我不喜欢这个词”“这里没有作者态度”“句子太长”，不能直接成立。


## 1.5 Preserve before repair

找到 finding 后，先标出附近**不能顺手磨掉**的内容：

- 有证据的来源核对痕迹；
- 会改变结论的未知项；
- 确实发生的判断变化；
- 有工作的数字、动作、失败或原话；
- 技术保护区；
- 由材料自然形成的长短不均与停顿。

修复只解决 finding。本来已经成立的“不规则”不是噪声。

## 2. 常见问题动作与修复

| 问题动作 | 典型症状 | 首选修复 |
|---|---|---|
| 重复解释 | 后段换说法重复前段结论 | 删除后段或合并新增信息 |
| 对象断裂 | 下一段突然换对象，关系不明 | 重排一两句或补最短关系句 |
| 背景过早 | 大段历史当前用不上 | 删除或移到真正需要处 |
| 抽象悬空 | “更稳定/更重要”后无依据 | 接回已有数字、动作、结果 |
| 名词化动作 | “进行了优化/实现了提升”让动作与结果变模糊 | 恢复主体、直接动词或可观察结果 |
| 来源说明泄漏 | 多段反复“公开资料显示/目前无法确认” | 合并为一次最有用的来源边界说明 |
| 装饰性具体 | 无来源的时间、天气、摆设只负责显得真实 | 删除；有来源且改变理解时保留 |
| 评论过载 | 连续几段都在判断 | 保留有证据的一处，其余删 |
| 自动升维 | 局部事实突然推到时代/行业 | 回到当前对象和边界 |
| 机械反转 | 反复用「不是 A 而是 B」，A 是读者未必这么想的假目标（名气最大 / 装饰品 / 必需品）| 直接陈述 B（往往是 X / 其实是 X / 更适合 X）；A、B 是真对比时保留 |
| 伪标题 | continuous 正文用 PART/H3/粗体标题 | 删除标题，让首句承担内容 |
| 无用分节 | sectioned/hard technical 把每个 coverage item 机械变成标题 | 合并没有导航价值的相邻小节；保留真正帮助定位的标题 |
| 技术侵蚀 | 为节奏删参数、条件、代码 | 恢复技术细节 |
| 完成后续写 | 正文已闭环，末段再总结 | 删除尾段 |

## 3. 四类安全改法

### Delete / Compress

适合：重复、空评论、自动总结、无来源修辞。

优先删，不寻找“更人味”的替代句。

### Clarify

适合：指代不清、主语过晚、条件关系混乱。

目标是更快出现对象和动作，不是统一改成短句。

### Transition

适合：两个相邻内容确有逻辑关系但当前没写出来。

只补最短必要关系。例如：

```text
失败主要集中在长 JSON，所以后面比较成本时，我把重试次数也算了进去。
```

不要写“说完稳定性，我们再看成本”。

### Evidence Exposition

适合：判断已有证据，但正文没把证据与结论关系说清。

只解释已有材料，不新增事实。

## 4. 字面形式不是 finding

以下单独出现都不需要修：

- 冒号；
- 破折号；
- “其实 / 不过 / 所以 / 比如”；
- 正常问句；
- 一次真实的“不是 A 而是 B”对照；
- 单句成段；
- 长段落；
- 不均匀段落长度。

只有它们反复承担同一种坏动作，例如连续翻案、连续制造洞察路标，才处理动作本身。机械反转是其中一类：反复的「不是 A 而是 B」里，A 常常是读者未必这么想的假目标，先否定一个不存在的立场再反转，是在制造假对比——直接说 B 通常更自然。

## 5. Refiner 禁止扩大范围

局部 finding 不允许顺手：

- 重写开头；
- 增加作者故事；
- 新增评价；
- 加 H2；
- 删除没被 finding 指向的技术块；
- “统一文风”；
- 重写结尾以追求力量感。

修完就停。

## 6. 三种结果对照

### 需要修改：报告腔遮住动作

```text
原文随后介绍了环境变量的优先级。材料显示它会覆盖文件配置。
→ 环境变量会覆盖文件配置，所以排查“配置没生效”时先看进程环境。
```

来源边界已在前文说明，这里直接交代机制与动作。

### 应该保留：自然原稿已经成立

```text
自动化省下的不是所有时间。它把重复操作交给脚本，也把异常处理的责任推到设计阶段。
```

这两句有判断、有动作、有节奏，不因“精修”换同义词，也不删除那个自然停顿。

### 修改过度：伪经历与技术侵蚀

```text
过度修改：我在线上被重试坑惨了，所以记住，少重试。
原文事实：timeout=3，attempts=2；写操作只有具备幂等条件才适合自动重试。
```

前者把报告腔改成虚假亲历，还删掉参数与适用条件。修复应恢复技术事实；若要表达选择，可写成明确的条件推演，不声称已经发生。

## 7. 最后冷读

Refiner 完成局部修复后只做四个判断，不开启新一轮美容：

1. 修掉的地方是否真的更清楚，而不是更整齐；
2. 是否误删了来源、边界、失败或真实判断变化；
3. 是否新增了原 finding 不需要的解释、金句或转场；
4. finding 已经解决时是否立即停止。
