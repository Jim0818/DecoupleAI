# 选题发现

从本次用户目标、当前账号 L1/L2、真实问题和已选素材出发。已明确具体主题时直接核查该主题，不先做全网热点巡检。常青教程可以由持续存在的读者任务触发，不需要借一条新闻证明时效。

## 范围与输入

L1/L2 提供账号的内容范围；本任务选择的策略、题库片段和成果登记通过 `input_refs` 传入，可用 `purpose: topic_scope` 等有意义的标签说明用途。只读取与当前任务相关的部分，不扫描全部账号、整库或历史运行。外部策略先经 kb-bridge 取得可用材料；没有读到当前来源时，说明本次以 L1/L2 和用户目标为依据、外部策略尚未核实，不把旧脚本中的策略副本当成现行要求。

主流工具和 Agent 的入门、任务教程、试用、比较均可成为选题；根据读者任务和账号方向确定归属。普通使用教程不以源码拆解、行业判断或先学会 Skill 为准入条件。需要判断资料能支持哪种内容形态时，读 [工具教程与试用](tool-trials.md)。

## 线索与判断

区分原始来源、需求信号、编辑想法与实际试用材料。官方文档或发布记录支持产品事实；问题帖、Issues、搜索趋势帮助发现问题，不自动证明普遍需求；编辑想法是待研究的方向；试用结论需要真实执行记录。检索热度和工具分值不能弥补事实缺口。

对每个候选说明：触发它的读者问题或变化；读者能带走什么；现有证据可支持哪些内容；与已选成果登记相比的新意；还需补什么资料或最小实验。比较读者价值、具体细节、证据、时效与工作量，给理由，不给模型加权小数分。

排除严重重复、与当前范围不符、只能靠夸大或虚构经历成立的候选。尚未找到证据但问题具体的想法可标为 `needs_research`，说明补证动作；不要将它写成已核实结论或直接交给写作冒充事实。只剩一项有价值候选就交付一项；没有合适候选时说明原因。可选来源不可用要单独说明，不能把检索失败写成“没有相关内容”。

题库与 registry 的旧栏目名称、状态和历史记录按来源保留。存在别名映射就使用已登记映射；状态冲突同时记录原值和出处，标明待核实，不自行挑选“已发布”或用新判断覆盖旧记录。无法核实的数字与标题主张保持待核实。
