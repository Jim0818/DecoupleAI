# 证据与验证

保存被当前内容使用的信息：来源身份、精确位置、版本或时间范围、关键主张、支持证据、条件和不能证明的内容。普通背景与每一句过渡不需要另建台账。

技术细节不能为了缩短过程记录而删除。API、配置、参数、代码、实验条件、失败模式和来源限制，都按读者任务保留足够内容与出处。

区分官方文档、官方自报结果、源码阅读、第三方测试与本次实际执行。官方 benchmark 不等于本次 benchmark，项目代码不等于整个产品的运行保证；来源变化时同步调整措辞边界。

对时效事实记录检查日期与适用版本。数值比较保留测试条件、单位、基线和测量口径；不把不同来源的测量、估算和推断混成同一测试表。

实际验证先确定允许环境与最小实验，记录真实命令、输入及观察到的结果。不可运行时交付静态检查或文档证据并说明缺口，不能为补齐验收表声称成功。

引用资料中的用户、作者或其他人的经历，不得转为当前作者亲历。真实作者材料只在能改变事实解释或任务完成时使用。

## 按需结构校验

任务明确选择结构化 evidence kernel 时，可运行 `PYTHONPATH=src python -m textpicos.content.validate_research_evidence <任务选定的kernel.json>`。它只校验当前 evidence-kernel 数据结构、ID 唯一性与 `claims.evidence_ids` 引用完整性；通过不代表来源事实已核实或代码已真实执行。

普通研究不因此增加必交台账。已有可消费的证据就按引用交付，只在当前任务需要结构化交换或校验时使用此工具。
