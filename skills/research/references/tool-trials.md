# 工具教程与试用

用于工具和 Agent 的选题、研究及必要验证。先确定读者要完成的任务与现有证据，再选择适合的内容形态；下表不是必经阶段，也不要求每篇内容同时覆盖多种形态。公共主张遵循 [Claim Evidence Policy](../../../config/policies/writing/claim-evidence-policy.md)。

| 内容形态 | 准备到什么程度 | 可以交付什么 |
|---|---|---|
| 资料解读 | 核实当前官方文档、发布记录或源码及其适用产品、版本 | 说明能力、适用任务、机制和限制；清楚保留资料来源 |
| 使用教程 | 明确前提、入口、关键步骤、输入示例和结果检查方法；说明步骤来自文档还是本次操作 | 让读者能够开始并检查任务结果；未执行的步骤不称为“已跑通” |
| 实际试用 | 在获准环境中真实执行选定任务，保留输入、条件、输出引用与观察记录 | 描述本次结果、失败、需要人工介入的位置和适用边界 |
| 对照比较 | 先明确比较问题与证据口径；实测结果保留任务、环境与设置，资料对照保留各自来源 | 给出在明确条件下的差异和选择依据；不把资料表、官方自报与本次测量拼成实测排名 |

## 最小可用材料

按任务保留产品形态（如网页、桌面应用、CLI）、核查日期、相关版本或套餐前提、读者任务、必要操作和结果检查方法。权限、费用、可用地区与数据处理方式只在影响任务选择或操作时核实；不要凭旧教程或品牌名称迁移结论。

实际执行记录说明谁执行、在哪种环境中执行、用什么输入、观察到什么，以及哪些环节没有执行。保存会被文章消费的原始输出、截图、日志或结果文件引用；无需为简单任务制造整套实验报告。失败与人工修正如实记录，未测项目保持未测。

区分当前 Agent 执行、作者本人操作、作者长期使用和第三方经历。当前 Agent 的一次成功可支持对本次任务结果的描述，不能写成作者“我长期使用后发现”；第三方案例也不能转成作者亲历。首次尝试失败仍可形成有用教程或避坑内容，结论限定到实际条件。

没有执行条件时，可以交付有出处的使用说明、静态机制解读或待执行的试用计划，并明确缺口。不要补写虚构的耗时、成功率、成本、截图、失败过程或推荐排名。工具介绍无需强行加入源码分析、行业升华或通用工作流。
