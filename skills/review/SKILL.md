# 内容与标题审阅

先核对任务提供的审阅范围、成果版本、读者任务和相关证据。先形成自己的判断，不用生成者的自我肯定或自评分代替核查。没有独立执行上下文时报告缺失。

## 审阅次序

1. 事实、技术表述和来源身份是否正确。
2. 当前任务承诺的内容是否讲清，代码、步骤和参数是否足以支撑其声称。
3. 版本、测量条件、适用范围、失败模式和不确定性是否诚实。
4. 正文、标题、摘要和图形的事实承诺是否一致。
5. 段落是否有推进，取舍、例子与判断是否有作用，是否满足本次明确的表达要求。自然度反馈也需定位到重复、跳步、身份错置或过度改写等具体问题。

自然表达判断使用共享 `natural-prose` 的 review 模式。不把无第一人称、无观点、无反转、无金句、允许范围内的小节或朴素语气当缺陷。

## 模式

- `review`：将当前正文及标题摘要作为一个内容整体审阅，避免另起固定标题裁判阶段。
- `review-changes`：先审改动和必要上下文；论点、关键条件、代码行为、主要顺序或开头结尾的改动可能影响全文连贯性，按实际影响扩大检查。保留未受影响的结论，不用改动字数决定是否复核。
- `title`：先排除夸大效果、范围、时效或受众，虚假权威、经历、收益，以及正文无法兑现的承诺；再按具体读者价值、主体辨识和自然表达比较有效候选。可以保留有依据的悬念和力度，不做加权小数打分。

## 输出

没有实质问题就返回 `PASS` 和任务提供的被审版本引用；不得用旧版本 PASS 代替新稿核对，也不自行编造哈希。存在问题时，每条只写位置、具体问题、读者影响和最小必要修改；证据问题指出来源。不另生成长审稿报告，不为证明审阅有用而要求全文润色。

问题按实际性质交主管安排：局部表达由写作修订，内容缺失由写作补充，事实不足补研究，图形问题改对应图。不得要求作者虚构经历或加强判断，也不在审阅任务里直接改稿。
