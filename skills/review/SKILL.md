# 内容与标题审阅

先核对本次审阅范围、成果版本、读者任务和相关证据。没有独立执行上下文时报告缺失，不能用换角色称呼代替独立审阅。

## 审阅次序

1. 事实、技术表述和来源身份是否正确。
2. 当前任务承诺的内容是否讲清，代码、步骤和参数是否足以支撑其声称。
3. 版本、测量条件、适用范围、失败模式和不确定性是否诚实。
4. 正文、标题、摘要和图形的事实承诺是否一致。
5. 逻辑、导航和表达是否真正损害理解，而非是否符合固定句式。

自然表达判断使用共享 `natural-prose` 的 review 模式。不把无第一人称、无观点、无反转、无金句、允许范围内的小节或朴素语气当缺陷。

## 模式

- `review`：将当前正文及标题摘要作为一个内容整体审阅，避免另起固定标题裁判阶段。
- `review-changes`：先审具体改动及其直接影响；发现事实主张、版本或范围改变时，指出相关对象再扩大检查。不能因一次续改要求全文重做。
- `title`：先排除夸大效果、范围、时效或受众，虚假权威、经历、收益，以及正文无法兑现的承诺；再按具体读者价值、主体辨识和自然表达比较有效候选。可以保留有依据的悬念和力度，不做加权小数打分。

## 输出

通过时返回 `PASS` 和被审成果的版本引用，不生成独立 Markdown 审稿报告。存在问题时，每条只写位置、具体问题、读者影响和最小必要修改；证据问题指出相关来源。

问题按实际性质交主管安排：局部表达由写作修订，内容缺失由写作补充，事实不足补研究，图形问题改对应图。不得要求作者虚构经历或加强判断，也不在审阅任务里直接改稿。
