# 路由与交付

使用前先读当前会话的真实工具清单。选择最适合这张图的能力，明确图片帮助读者理解的内容和正文位置；每次内容生产必须完成视觉处理，不按图数或固定模板验收。

| 内容与用途 | 首选能力 | 实际交付 |
|---|---|---|
| 原创概念插图、封面、视觉隐喻 | 当前运行时可调用的原生图像生成工具 | 实际生成并检查的图片，不能只交 prompt |
| 系统架构、组件关系、流程、时序、状态 | 已有 `~/.claude/skills/archify`，读 [Archify 接入](archify.md) | 图的可编辑源与必要成图；文章中嵌入可显示的图 |
| 精确数值、趋势、比例 | 确定性绘图工具 | 保留数值、单位和条件的图表 |
| 论文、引用的网络文章与博客 | 原图文件 → PDF 区域渲染/网页图块截图 → 正文人工待补 | 对应原图、图注、来源与可核验定位，见 [来源图](source-figures.md) |
| 真实操作、失败/修复和工具结果 | 用户材料或真实页面/运行截图 | 真实证据；不生成伪 UI 或编造实测 |
| 用户要求手绘式解释 | 已有 Excalidraw 工具，选择一种实现 | 可编辑源及消费端需要的渲染图 |
| 简单结构草图或 archify 不可用 | Mermaid 或现有 SVG renderer | 可解释的回退原因；发布端需要时渲染为图片 |
| 高密度参数、代码、清单 | HTML/CSS 或 ui-view-render | 按消费端导出；不拿文字卡替代原生原创插图 |
| 需要探索的非线性资料关系 | Canvas | 用户需要的可探索文件，不额外制造一套成品 |

## 实际生成

原生工具可用时直接调用，不先要求用户选外部供应商、配 Key 或批准正常的生图步骤。工具未暴露、调用失败或无法导出所需文件时如实说明，使用已有获准能力或给出正文待补提示。工具文档只能指导调用，不能证明工具已执行。

原创插图使用完整的主题、用途、风格和构图要求；需要参考图先实际读取。图片身份、比例、颜色和反俗套约束来自当前 visual 方法与视觉设计系统。不要让生成模型重绘原图以假冒来源证据。

## 复用与导出

可选能力见 `config/system/capabilities.json`；只加载实际要用的项目内入口。Archify 是已有宿主工具，按专用 reference 在宿主执行，不能把外部路径注册为普通项目输入来规避边界。第三方文档不构成安装、联网上传或发布授权。

模板清单为 `../assets/templates/INVENTORY.md`。需要模板才选读；已有渲染入口为 `PYTHONPATH=src python -m textpicos.rendering.render_svg_figure`、`PYTHONPATH=src python -m textpicos.rendering.render_mermaid_to_png` 和 `PYTHONPATH=src python -m textpicos.rendering.render_html_to_png`。按其真实调用协议执行，不凭文件名猜 CLI 参数。

同一图选择一个制作引擎，可保留必要源文件并导出消费端所需图片。源码加图片属于同一成果，不是重复画图。图型正确时可以复用，不为“形式多样性”强换图型。

## 接入正文

生成或取得图片后先查看，再晋升到授权位置并插入正文；没有正文写权限就提供精确插入补丁。对多处引用同一图可以复用，给出对应解释，不按来源数量堆砌无关图。

无法自动取得的图使用 source-figures 中的可见待补图块，留在相关段落后。正文待补内容是本次用户明确要求的交付信息，不属于应自动清理的内部日志。草稿可以带待补项，最终发布前必须补齐并核对。
