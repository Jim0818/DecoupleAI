# 来源图与人工补图

在正文引用论文、网络文章或博客内容时使用。目标是让图片直接对应读者正在读的事实；先查看来源，不用搜索缩略图、同作者其他文章或品牌封面充数。共用同一来源图能说明多处内容时复用即可，不机械规定一来源一张图。

## 论文

1. 打开实际论文 PDF 或作者提供的正式 HTML；核对版本、标题、图号、图注及相关正文。只读到摘要、搜索片段或二手介绍时不能声称已经查看原图。
2. 先查看相关页或图的实际画面，确认完整边界、子图、坐标轴、图例和必要图注。以已看过的页面选择截取区域，不猜坐标。
3. 有完整原始图文件时优先取得原图。PDF 中只有位图对象时可提取；图含矢量线条、标签和多个对象时优先渲染整幅 Figure 区域，避免单独提取某张内嵌图片导致文字或子图缺失。
4. 可用当前 PDF screenshot 工具，或已安装 PyMuPDF 的 `page.get_pixmap(clip=..., dpi=...)`。页面编号以工具的实际零/一起始规则转换，给用户的 PDF 页码使用从 1 开始的页序，并与印刷页码区分。
5. 查看导出结果，保留原始数值、图例和图意，不改变坐标轴、删去关键对照或生成假数据。图注写明作者/论文、年份、Figure 编号与原文链接；不确定的信息明确留待核实。

## 网络文章、博客与文档

1. 打开实际引用的原网页及相关小节，查看该段配图和图注。记录原网页 URL、已确认的小节/图标题和图片直接地址（能取得时）。
2. 优先下载真实原图并检查文件；链接若返回 HTML、低清缩略图或登录页，不算已取到图片。
3. 原图无法完整取得而页面可见时，使用可用截图工具截取对应图块，保留说明图意所需的上下文。截图工具、页面和网络条件依当前宿主为准；不假称自己拥有不存在的浏览器会话。
4. 原文没有图片时，可以截取与所引论点直接相关的图表、代码或页面片段，图注准确标为“原文片段截图”。不能拿无关图片充数；不适合截图或无法访问就转人工待补。
5. 保留作者、出处、必要水印与已知使用条件；截图不自动改变来源的复用条件。确实不可直接复用时说明具体原因并请求用户提供可用素材，或制作清楚标为“根据来源整理”的原创示意，不能冒充原图。

原图中必要的 Logo、标签、文字或更多颜色属于证据的一部分，不套用原创封面的去文字、限色或去 Logo 规则去改造来源图。

## 正文定位与图注

将图放在解释该事实的段落后，或最接近论证位置的地方。定位优先用段落首句/末句、明确小节或既有 claim 标识；不依赖“第几个 H2”，无小节文章同样适用。

已取得图片时使用真实可解析的资源引用，并用图注明确“来源原图 / 原文截图 / 根据来源重绘 / 概念示意”的身份。必要记录直接写入现有任务结果或来源记录：来源 URL、原图定位、本地真实路径、正文位置、图注和取得方式。不要每张图再造一个报告。

## 无法取得时：正文可见待补

先完成可执行部分，再在对应段落后写下面的可见引用块。不能只放进发布元数据、文末附录或员工回复；不能使用隐藏 HTML 注释代替。

```markdown
> 【待补图｜论文原图】
> 来源：[已核实的论文标题](实际论文链接)。
> 定位：PDF 第 N 页，Figure X（仅填写实际核实过的页码和图号）。
> 请截取：完整结果图，保留左右子图、坐标轴、图例和必要图注。
> 用途：放在本段之后，说明正文正在讨论的对比。
> 建议图注：图 X｜对应内容说明。来源：论文作者，年份，Figure X。
> 原因：当前无法取得完整且可核验的原图，需你补充截图。
```

博客使用 `【待补图｜博客原图】`，填写真实 URL、已确认的小节名、目标图特征与裁切范围。若未打开论文或网页，写“页码/图号（或小节）尚未核实，请提供相关原图”，不要保留 N/X 模板或编造定位。

原创生图工具不可用或已实际失败时，使用 `【待补图｜原创插图】`，提供画面目的、具体内容、比例与风格，以及真实失败原因；完整可用提示词可放在该块内。提示词仍不算已生成。

网页/论文有已查看的图但下载失败，和根本没有看到来源图，要分别写清。源站临时不可访问时不要先要求用户补图后停止其他工作。

## 状态与完成

- 已有真实图片且看图核对过：插入并说明必要来源。
- 未取得图片或尚未完成必要核对：保留对应待补图块，向主管和用户报告为待补草稿。
- 用户补图后：读取实际图片，确认图号、裁切、清晰度及论点对应，再替换该位置提示并同步引用。
- 不以删去待补提示、写假路径或把来源图换成生成插图的方式宣称完成。
- draft 交付允许保留具体待补图说明；final 发布校验检查可见待补图标记。最终发布前补齐真实资源并重新交付，沿用现有发布授权边界。
