# 文章交付兼容

只在交付正式文章、处理文章元数据或准备明确请求的发布时使用。权威格式为 `config/contracts/content/article-output.schema.json`，实际校验与发布入口负责机器检查；不要从旧 phase 导出一套新的固定写作步骤。

## 文章文件与元数据

已有文章先保留文件名、slug、run_id、account_id、date、column、tags、published_to 和其他有效字段。纯措辞修订只动指定正文；标题任务只修改标题及直接对应的公开文案。不要重生成整稿、重建 run 或擅自更换账号、栏目、发布时间。

新正式文章使用 schema 要求的 YAML frontmatter：`title`、`slug`、`run_id`、`account_id`、`column`、`date`、`tags`、`published_to`。run_id 来自实际运行，不能临时编造；账号与栏目来自当前任务及账号配置；未发生发布就不能填写已经发布的状态。tags 为字符串列表，published_to 保持消费端接受的字符串或字符串列表。

文件名遵守 `YYYY-MM-DD-slug.md`，按当前账号命名约定可使用 `_studio` 或 `_intellifuture` 后缀；slug 为小写英文/数字与单连字符。不要因标题润色自动改 slug 或文件名。字段缺失且无法从已授权输入可靠确定时，明确列出缺口。

## 正文与资源

正文只保留读者会读到的内容，开场白就是正文开头。保留代码、命令、引用、图片标记与原有可用链接；移动资源或重命名文件必须符合任务允许范围，并同步直接引用。不得用不存在的图片路径或生成提示词替代实际资源。

`metadata_sections`、`visual_asset_paths` 与 H2 列表/长度由内容适配器从文章和已选资源提取，不在正文末尾塞入 JSON 契约或手写派生 H2 清单。没有视觉资产时不强制造图；有资产时保持源文件、导出文件和文章引用的一致性。

## 按实际发布接口选 profile

普通新稿使用与任务一致的 draft/内容 profile，不默认生成发布包。现有 legacy `final` profile 要求的最终标题、备选标题、开场白、核心摘要、引流文案、SEO、视觉资产和封面提示词属于该发布适配器的兼容输入；只有实际选择该接口时，才按其要求补必要信息到发布元数据，不把这些栏目加成新默认中间产物。发布前需用户明确指令，写完文章不等于已经发布。

仅当任务确为 Skill 系列时加载 schema 的 `skill_article` 相关字段和真实核验边界。`measured_evaluation` 必须有实际运行证据；静态阅读、接口试验、情景演练与构建记录分别如实标记，不能为通过旧检查提升证明强度。

## 新主管运行的发布校验

新主管运行按当前完成批次中的正式交付版本校验，不要求旧 phase 报告或 legacy final 的整套发布元数据。正文以及被正文引用的图片必须已经作为本次运行交付，文件哈希和大小与完成记录一致；修订后须再次完成交付。--force 不能绕过这些条件。

现有发布适配器要求新运行的本地图片存放在 articles/pending/visuals/<run_id>/，并在正文使用有效相对引用。视觉员工先写 staging，主管通过运行时将所需图片晋升到该正式目录并登记为交付；不得仅把任意临时路径写进正文。发布时只复制正文实际引用的图片并改写对应链接，不复制整个中间报告目录，源图和未引用文件保留。只有文章实际需要图片时才使用此约定；纯文字短稿无需补图。
