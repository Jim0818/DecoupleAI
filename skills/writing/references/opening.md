# 开头与承诺

仅在起草正式开头，或当前任务指出开头绕远、对象不清、承诺过大时使用。开头属于同一稿件，不单独设置一个岗位或必交文件。

## 让读者尽早进入主题

第一段尽早给出对象、问题或动作。必要的版本、环境和适用范围放在影响理解的地方，随后给出文章能够兑现的解释、结果或操作路径。已自然有效的开头直接保留。

按真实材料选择入口：已经发生的变化或结果、来源中的具体发现、一个有解释价值的细节、教程要完成的任务、决策需要的条件。假设场景必须清楚标为假设，只在它能帮助理解时使用；不能借虚构痛点、用户反馈或亲历提高吸引力。

## 针对问题修复

| 实际问题 | 修复 |
|---|---|
| 背景太长，对象到第二屏才出现 | 提前对象和有用信息，背景随解释需要补入 |
| 只是换词重复标题 | 加入标题没有交代的范围、机制或判断依据 |
| 承诺超出正文与证据 | 缩小承诺，或请求补齐会影响结论的材料 |
| 把推测、假设或转载写成亲历 | 恢复来源和证据身份，删除虚构体验 |
| 一直设问而不给答案 | 先给能成立的回答，再解释条件与过程 |

只在确需比较入口策略时提出候选，不规定候选数量、情绪强度或开头模板。局部修复不扩成全文重写。

交付前核对：入口是否真实、范围是否清楚、首个有用回答是否及时、正文是否兑现承诺。把修复落在正式稿；只有主管的具体任务要求时才附必要理由，不另写开头追踪报告。
