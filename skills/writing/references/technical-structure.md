# 技术内容组织

选择帮助读者完成任务的结构，而不是固定标题数量：

| 任务 | 可采用的理解顺序 |
|---|---|
| 机制解释 | 定义与依赖 → 机制 → 数据/控制流 → 示例 → 边界 |
| 教程 | 结果 → 前提与环境 → 步骤 → 验证 → 常见失败 |
| 工程实践 | 问题与约束 → 实现 → 实验 → 结果 → 取舍 |
| 比较决策 | 问题 → 标准 → 证据 → 权衡 → 有条件的结论 |

这张表是内部参考，不是公开 H2 模板。代码、配置、参数、实验条件与失败模式可以占据主要篇幅；不为作者评价或“洞见”预留配额。

按读者的理解或操作需要分配篇幅。例子解决具体困难，步骤交代必要的预期状态与失败条件；同一机制可以连续展开，不必给每个知识点同等长度。

保留帮助理解来由的真实反应和自然停顿，不要求每段只装新增事实。合并没有新作用的复述，删去无依据的意义升级；资料薄就缩小范围或补关键材料，不用叙事掩盖缺口。
